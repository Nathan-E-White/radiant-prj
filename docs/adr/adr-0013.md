# Coherent Workbench Snapshot And Lifecycle Reconciliation

## Status

Accepted

## Context

The Workbench has one Browser read module that accepts a complete, generation-bound Snapshot. The gateway nevertheless retained field-wise read routes and controller/store methods for state, measured frames, Twin State, and selected Lineage. Those routes allow a caller to assemble different generations and leave a stale browser client and operational proof path that contradict the coherent-read rule in ADR-0007.

Dynamic measured-frame retention was also performed by `Snapshot()`. A read could therefore delete rows, advance generation, and fail because cleanup failed. The same retention work already has an explicit periodic reconciliation path, but that path aggregates task failures into logs and does not establish scheduler readiness, task-specific health, or cancellation semantics.

## Decision

The public Workbench read interface is exactly one authorized `GET /api/simulator-workbench/snapshot`. It returns a complete `WorkbenchSnapshot` for one committed generation. The retired state, measured, twin, and selected-lineage routes must not be retained as compatibility paths, optional Snapshot fields, or Browser fallback paths.

`Snapshot()` is a pure read. Dynamic measured retention is an explicit lifecycle reconciliation command. A successful prune advances the visible generation only when it changes projected rows; a Snapshot read never prunes, advances generation, or resets lifecycle health.

The Workbench depends on a narrow Snapshot reader interface. InMemory and Postgres are real adapters for that interface. Twin Projector restart hydration is a separate internal projection-query interface for bounded latest measured frames and results. It is not part of the public Snapshot reader.

The Snapshot envelope is an executable cross-runtime contract. A canonical envelope schema composes constituent schemas; shared valid and invalid vectors cover required constituents, value-basis rules, and generation equality. Go adapter/handler tests and Browser adapter tests consume the contract. Generated browser clients and a second field-read client are not introduced.

Lifecycle reconciliation reports independent named outcomes for Reactor expiry, Artifact Forge expiry, and measured retention. Scheduler health begins as `starting`, runs one full initial cycle, then becomes `ready`, `degraded`, or `not_ready` according to explicit task criticality and deadline policy. `/healthz` remains process liveness; `/readyz` renders static configuration plus this lifecycle policy; `/metrics` remains scrapeable in every state and exposes bounded task outcome metrics. Scheduler cancellation is passed through every lifecycle task; shutdown cancellation is not recorded as an operational task failure.

Operational evidence proves one Snapshot after scheduler-driven work. Smoke scripts that need a settled gateway wait on `/readyz`; process supervision uses `/healthz`.

## Consequences

Browser callers learn one read interface and cannot field-wise assemble Workbench state. Coherence, transaction isolation, and projection construction remain local to the InMemory and Postgres adapters. Twin Projector retains only its genuine hydration queries.

Retention cleanup is observable even when no Browser reads occur. The price is explicit scheduler state, startup behavior, cancellation, metrics, readiness policy, and delivery evidence. A recovery failure is visible without creating a restart loop or making a valid Snapshot unreadable.

The detailed module, contract, lifecycle, and verification rules are recorded in [Workbench Snapshot Read And Lifecycle Policy](../design/workbench-snapshot-read-and-lifecycle-policy.md). ADR-0007 remains the governing Live Read Boundary decision; this decision makes its read-only and operational consequences explicit.
